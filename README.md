# AI Practical Assessment

Drupal 11 application managed with Composer and DDEV. No Node.js or frontend build tooling.

**Ticket system docs (setup, tests, API, limitations):** [`ai-practical-assessment/README.md`](ai-practical-assessment/README.md)

## Stack

| Component | Version / choice |
|-----------|------------------|
| CMS | Drupal 11 |
| PHP | 8.3 (in DDEV) — no host PHP required |
| Web server | Nginx + PHP-FPM |
| Database | MySQL 8.0 (default; MariaDB switchable) |
| Local env | DDEV + Docker |
| CLI | Drush 13 |
| Package manager | Composer 2 (via `ddev composer`) |
| Frontend | Twig + vanilla JS (no Node.js / npm) |

## Prerequisites

- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (or compatible Docker runtime)
- [DDEV](https://ddev.com/get-started/) v1.24+
- Git

Do **not** run Composer or PHP against this project on the host. Use DDEV wrappers so PHP 8.3 and the project lockfile stay consistent. Node.js is not needed.

## Quick start

```bash
# Clone and enter the project
cd ai-practical-assessment

# Start containers (MySQL 8.0, Nginx, PHP 8.3)
ddev start

# Install PHP dependencies (if vendor/ is missing)
ddev composer install

# Install Drupal (Standard profile) — skip if already installed
ddev drush site:install standard \
  --account-name=admin \
  --account-pass=admin \
  --site-name="AI Practical Assessment" \
  -y

# Enable ticket module, schema updates, seed demo users
ddev drush en ticket_management -y
ddev drush updb -y
ddev drush cr
ddev drush php:eval "print_r(ticket_management_seed_demo_users());"

# Open the site
ddev launch /tickets
```

Site URL: https://ai-practical-assessment.ddev.site · Tickets UI: `/tickets`

Local admin (after the install command above): `admin` / `admin` — change after first login. Demo users: see [`ai-practical-assessment/database/seed-data/README.md`](ai-practical-assessment/database/seed-data/README.md) (password `TicketDemo!23`).

## Common commands

```bash
ddev start                 # Start environment
ddev stop                  # Stop environment
ddev describe              # URLs, ports, DB credentials
ddev ssh                   # Shell in web container
ddev composer <cmd>        # Composer (always prefer this over host composer)
ddev drush <cmd>           # Drush
ddev drush cr              # Rebuild caches
ddev drush cex -y          # Export config → config/sync
ddev drush cim -y          # Import config from config/sync
ddev xdebug on|off         # Toggle Xdebug
ddev mailpit               # Catch outbound mail in Mailpit
```

## Database: MySQL ↔ MariaDB

Default is **MySQL 8.0** in [`.ddev/config.yaml`](.ddev/config.yaml).

To switch to MariaDB:

```yaml
database:
  type: mariadb
  version: "10.11"
```

Then:

```bash
ddev restart
# For a clean empty database after switching engines:
# ddev delete -Oy && ddev start && ddev composer install && ddev drush site:install ...
```

## Custom code

- Modules: `web/modules/custom/`
- Themes: `web/themes/custom/`
- Profiles: `web/profiles/custom/`

Add contrib packages with Composer only, for example:

```bash
ddev composer require drupal/pathauto
ddev drush en pathauto -y
```

## Configuration management

`$settings['config_sync_directory']` points to `../config/sync` (see `web/sites/default/settings.php`). Export and commit config from that directory.

## Notes

- Host Composer (if older than 2.7) may fail on Drupal 11 plugins — always use `ddev composer`.
- This project intentionally does not use npm, yarn, pnpm, webpack, Vite, or Gulp.
- `settings.ddev.php` is generated by DDEV and listed in `.gitignore`.
